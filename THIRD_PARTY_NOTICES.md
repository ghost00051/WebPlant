# THIRD_PARTY_NOTICES.md — сторонние компоненты и лицензии

Документ фиксирует сторонние зависимости WebPlant, их лицензии и обязательства при
распространении. Значения лицензий взяты из поля `license` в `package.json` установленных
пакетов (`node_modules/...`) и из `package.json` проекта; версии — на момент составления
документа.

Проверить актуальный состав можно так (PowerShell):

```powershell
foreach ($p in 'Backend','Frontend') {
  $pkg = Get-Content "$p\package.json" -Raw | ConvertFrom-Json
  $names = @($pkg.dependencies.PSObject.Properties.Name) + @($pkg.devDependencies.PSObject.Properties.Name)
  "=== $p ==="
  foreach ($n in $names) {
    $f = Join-Path $p "node_modules\$n\package.json"
    if (Test-Path $f) {
      $d = Get-Content $f -Raw | ConvertFrom-Json
      "{0}`t{1}`t{2}" -f $n, $d.version, $d.license
    } else { "{0}`tне установлен" -f $n }
  }
}
```

Полный текст каждой лицензии — в `node_modules/<пакет>/LICENSE*`.

## 3. Лицензии, требующие внимания

### 3.1 MPL-2.0 — `web-push`, `lightningcss`

MPL-2.0 — file-level copyleft: можно использовать в закрытом продукте, но если вы
**изменяете файлы самого пакета**, исходники изменённых файлов должны быть доступны на
условиях MPL-2.0. Простое использование и распространение неизменённых пакетов
разрешено при сохранении уведомлений о лицензии.

* `web-push` входит в backend-образ (server-side). Файлы пакета проект не изменяет.
* `lightningcss` используется только на этапе сборки фронта и в `dist` не попадает.

### 3.2 LGPL-3.0 — `@img/sharp-*` / libvips

`sharp` распространяется под Apache-2.0, но платформенные бинарники `@img/sharp-*`
содержат libvips и заявлены как `Apache-2.0 AND LGPL-3.0-or-later`. При распространении
бинарников (например, если отдавать собранный образ с `sharp` третьим лицам) нужно:

* сохранить уведомления и тексты обеих лицензий;
* обеспечить возможность замены LGPL-компонента (динамическая компоновка libvips это
  допускает) и, по запросу, предоставить исходники libvips той версии.

Серверное использование внутри продукта (без распространения образа) обязательств по
предоставлению исходников не создаёт.

### 3.3 Apache-2.0 — `sharp`, `openai`, `dockerode`

Требуется сохранять copyright/NOTICE и текст лицензии при распространении; изменённые
файлы должны быть помечены. В репозитории сторонние файлы не изменялись.

### 3.4 MIT-0 — `nodemailer`

Самая либеральная формулировка MIT: уведомление о лицензии не требуется, но мы сохраняем
её в составе `node_modules` и этого документа.

### 3.5 ISC — `node-cron`, BSD-2-Clause — `dotenv`

Требуется сохранить текст лицензии и copyright при распространении.

## 4. Шрифт Inter

* В интерфейсе используется шрифт **Inter** (переменные начертания 400–700), файлы:
  `Frontend/public/fonts/inter-cyrillic.woff2`, `Frontend/public/fonts/inter-latin.woff2`,
  подключение — `Frontend/public/fonts/inter.css` (`@font-face`, `font-display: swap`).
* Лицензия — **SIL Open Font License 1.1 (OFL-1.1)**: шрифт можно использовать, встраивать
  в сайты и приложения, изменять и распространять вместе с продуктом; нельзя продавать
  шрифт отдельно, производные (при изменении) должны оставаться под OFL и не использовать
  зарезервированное имя Inter.
* **Текст лицензии в репозиторий не добавлен.** Рекомендуется положить `OFL.txt` рядом с
  файлами шрифта (`Frontend/public/fonts/OFL.txt`) и указать в футере/юридических
  документах; до этого обязательство по сохранению уведомления считается невыполненным.
* Источник файлов (официальный релиз Inter или сторонний конвертер) в репозитории не
  задокументирован — при следующей ревизии лицензий зафиксируйте источник и версию шрифта.

## 5. Иллюстрации и графика

* Изображения растений на публичных страницах (`Frontend/public/plants/*.svg`) **генерируются**
  скриптом `Frontend/scripts/generate-plant-images.mjs` из данных `Frontend/src/data/plants.js`.
  Это собственная графика проекта: сторонних лицензий и атрибуции не требуется.
* Иконки интерфейса (`Frontend/src/assets/*.svg`, `Frontend/img/*.svg`) — графика проекта
  (простые SVG-иконки, нарисованные для продукта); сторонние наборы иконок не подключены,
  сторонние библиотеки иконок в зависимостях отсутствуют.
* PWA-иконки `Frontend/public/icons/*` и `Frontend/public/favicon.ico` — графика проекта.
* Логотипы в `Frontend/src/assets/react.svg` и `Frontend/src/assets/vite.svg` — из шаблона
  Vite (проект Vite, MIT); в сборке **не используются**, товарные знаки принадлежат их
  правообладателям.
* Фотографии растений, загруженные пользователями, хранятся в `Backend/uploads` (вне git) и
  являются пользовательским контентом; проект их не лицензирует и не публикует как свои.
* Юридические документы в `Frontend/document/` (PDF/DOCX) — тексты проекта; файл
  `UserAgreementTemplate.*` является шаблоном и требует юридической проверки перед
  публикацией.
