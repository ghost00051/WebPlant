## 4. Находки по приоритетам

### P1 — исправить в первую очередь

#### 4.1. `sw.js` отдаётся с `Cache-Control: max-age=3888000` (45 дней)
**Где:** прод-nginx (в репозитории эталонный `Backend/nginx/conf.d/checktheplants-frontend.conf.example` уже содержит правильный `no-cache, no-store, must-revalidate` и `Service-Worker-Allowed: /`, но на проде не применён).
**Почему плохо:** обновления service worker и PWA-контента задерживаются; пользователи в Chrome/Safari/Edge могут неделями видеть старую версию приложения и старые метаданные при офлайн-навигации.
**Как исправить:**
```nginx
location = /sw.js {
    add_header Cache-Control "no-cache, no-store, must-revalidate" always;
    add_header Service-Worker-Allowed "/" always;
}
```

#### 4.2. На проде не включён Brotli
**Факт:** при `Accept-Encoding: br` ответ приходит без `Content-Encoding`; gzip работает. HTML/JS/CSS — только gzip.
**Почему плохо:** Brotli поддерживают все актуальные браузеры (Chrome, Firefox, Safari 11+, Edge); экономия 15–25 % на JS/CSS/HTML → LCP/INP и Core Web Vitals (фактор ранжирования Google).
**Как исправить:** включить `brotli on` + `brotli_types` в nginx (шаблон уже есть в репозитории), проверить `curl -I -H "Accept-Encoding: br" https://checktheplants.ru/assets/<chunk>.js` → `content-encoding: br`.

#### 4.3. `lastmod` главной = дата сборки; проверка `verify-build` требует «сегодня»
**Факт:** в `Frontend/scripts/prerender.mjs` для `/` пишется `lastmod: buildDate`; остальные страницы — `updated` из данных (2026-10-15). `Frontend/scripts/verify-build.mjs` (~строка 125) проверяет `lastmods.includes(today)`, поэтому `npm run verify` на устаревшем `dist` падает: **«sitemap: lastmod автоматический (есть дата текущей сборки)»** — это наблюдалось до пересборки.
**Почему плохо:** lastmod не отражает реальное изменение контента; поисковики со временем перестают доверять lastmod. Плюс ложные падения проверки у разработчиков/CI на несвежей сборке.
**Как исправить:** для `/` брать реальную дату изменения контента (или `buildInfo.builtAt`, но не «сегодня»); в `verify-build.mjs` сравнивать с датой из `build-info.json`, а не с `new Date()`.

#### 4.4. 14 из 24 title длиннее 60 символов (17 — от 60), максимум 72
**Факт:** `care-pochemu-zhelteyut-listya` — 72, `care-kak-chasto-polivat` — 70, `care-vlazhnost-vozduha` — 69; 14 страниц > 60 (ещё 3 — ровно 60).
**Почему плохо:** Google показывает ~580 px (≈55–60 символов для кириллицы), Яндекс — ещё меньше; ключевая часть и бренд «— Лейка» обрезаются.
**Как исправить:** сократить title до 50–60 символов, ключевой запрос — в начало, бренд — в конец или убрать (поисковики сами добавляют название сайта). Источники: `Frontend/src/data/siteMap.js` (секции), `Frontend/src/data/seoMeta.js` (карточки/статьи, генерируется `scripts/generate-seo-meta.mjs`).

#### 4.5. H1 главной — слоган без целевого запроса
**Факт:** H1 главной: «Помните о поливе.Наслаждайтесь ростом.» — запроса «полив комнатных растений» в H1 нет (он есть в title/description). У остальных 23 страниц H1 соответствуют запросу.
**Почему плохо:** H1 — прямой сигнал релевантности для Google и Яндекса по главному коммерческому/информационному запросу.
**Как исправить:** включить фразу в H1 (например, «Полив комнатных растений — календарь и напоминания»), а слоган оставить подзаголовком; либо добавить визуально скрытый, но доступный H1.

#### 4.6. Самоподписанный сертификат `admin.checktheplants.ru`
**Факт:** issuer = subject = `CN=admin.checktheplants.ru`, SAN пустой, срок до 10.10.2027. Chrome/Edge/Firefox/Safari показывают предупреждение и блокируют переход.
**Почему важно:** админка — не SEO-страница, но «для всех браузеров» она сейчас недоступна без обхода предупреждения; `robots.txt` на поддомене есть и закрывает его (`Disallow: /`), проблема только в сертификате.
**Как исправить:** выпустить Let’s Encrypt-сертификат на `admin.checktheplants.ru` (certbot), настроить автообновление; при желании — HSTS на поддомене.

#### 4.7. Нет подтверждения Google Search Console и Bing Webmaster Tools
**Факт:** в head есть `yandex-verification: 3eb0439788e93078`, но нет `google-site-verification` и `msvalidate.01`.
**Почему важно:** без GSC/BWT нельзя видеть ошибки индексации, запросы, Core Web Vitals и отправлять sitemap; Google может использовать данные GSC для улучшения сниппетов.
**Как исправить:** подтвердить ресурс через DNS TXT (предпочтительно для домена) или добавить мета-теги в `Frontend/index.html`; отправить sitemap; проверить `site:checktheplants.ru` в обоих поисковиках.

#### 4.8. Дубли URL со слэшем и двойным слэшем отдают 200
**Факт:** `/plants/`, `/care/`, `/plants/monstera/`, `/login/`, `//plants` → 200 (canonical корректно указывает на версию без слэша). `/index.html`, `/plants.html`, `/care.html`, `/plants-monstera.html` и т. п. → 301 (хорошо).
**Почему плохо:** дубли размывают сигналы, тратят краулинговый бюджет; canonical снижает риск, но 301 надёжнее.
**Как исправить:** добавить 301-нормализацию слэша на проде (это уже в бэклоге как T-10 в `docs/SEO.md`, §3.3); для `//` — `merge_slashes on` (в nginx включено по умолчанию, но проверить конкретный location).

#### 4.9. `og:type=website` и общая обложка у статей и карточек
**Факт:** у всех 24 indexable-страниц `og:type="website"`, `og:image="/og-image.png"`, нет `article:published_time`/`article:modified_time`/`article:section`.
**Почему плохо:** Telegram/VK/X/Facebook показывают одинаковую карточку для всех статей — ниже CTR; для статей корректнее `og:type=article`.
**Как исправить:** в `scripts/prerender.mjs` для карточек/статей ставить `og:type=article`, `article:published_time/ modified_time`, по возможности уникальный `og:image` 1200×630 на страницу (растр PNG/JPEG, не SVG — соцсети SVG не принимают).

#### 4.10. `Article.image` для карточек растений — SVG 800×600
**Факт:** JSON-LD карточек ссылается на `/plants/<slug>.svg` (800×600). Google для large image preview рекомендует ≥1200 px по ширине, 16:9 и ≥50 000 px².
**Почему плохо:** карточки не получают крупное изображение в расширенных сниппетах; SVG поддерживается Google, но размер меньше рекомендуемого.
**Как исправить:** сгенерировать растровые 1200×630 (или 1200×675) обложки для 10 растений и 11 статей и указать их в `Article.image` (можно массивом: PNG 1200×630 + SVG). Аналогично — для `og:image`.

#### 4.11. `manifest.json` отдаётся с `Content-Type: application/json`
**Факт:** `content-type: application/json` вместо `application/manifest+json`.
**Почему плохо:** спецификация W3C требует `application/manifest+json`; Chrome обычно терпит, но строгие тулзы/браузеры могут предупреждать.
**Как исправить:** в nginx:
```nginx
types { application/manifest+json json; }
location = /manifest.json { default_type application/manifest+json; ... }
```

#### 4.12. JS/CSS кешируются 45 дней без `immutable`
**Факт:** `cache-control: max-age=3888000` для `/assets/*`, иконок и `og-image.png`; HTML — `max-age=0, must-revalidate` (правильно); шрифты — 180 дней.
**Почему плохо:** имена ассетов хешированы, поэтому их можно кешировать на 1 год с `immutable`; 45 дней — избыточные перезапросы при повторных визитах.
**Как исправить:** `Cache-Control: public, max-age=31536000, immutable` для `/assets/` (как в эталонном nginx-конфиге и `.htaccess`).

**Инфраструктура (nginx прода):**
