# WebPlant

WebPlant — это full-stack веб-приложение на базе React + Express + PostgreSQL, разработанное в рамках учебного/экспериментального проекта. В текущем состоянии проект находится на ранней стадии разработки и активно дополняется, поэтому структура, функциональность и API могут меняться без предварительного уведомления.

Основная идея проекта на данный момент — предоставить базовую систему регистрации и входа пользователей, с поддержкой согласий на обработку персональных данных и cookie-согласий, а также с серверной логикой для работы с пользователями и юридическими/каки-согласиями.

Это не финальный production-ready продукт, а скорее рабочий прототип, который демонстрирует архитектуру приложения, взаимодействие frontend/backend, авторизацию, хранение пользовательских данных и обработку согласий.

## Обзор возможностей

На текущий момент в проекте уже реализованы базовые сценарии:

- Регистрация нового пользователя
- Вход по email и паролю

- Разделение проекта на frontend и backend

## Что уже реализовано

### Пользовательская авторизация

Backend содержит базовый набор методов для работы с пользователями:

- регистрация пользователя
- логин
- logout
- получение текущего пользователя
- получение списка пользователей

При регистрации выполняется ряд проверок:

- обязательные email и пароль
- проверка принятия согласия на обработку персональных данных
- проверка принятия пользовательского соглашения
- проверка существования пользователя с таким email
- хеширование пароля
- создание JWT и сохранение его в cookie

### Cookie consent

В проекте реализована система согласий на cookies. Это позволяет:

- сохранять согласия пользователя или гостя
- хранить тип согласия (
  technical,
  analytics,
  marketing,
  personalization
)
- отслеживать срок действия согласия
- отзывать согласие
- привязывать guest-согласия к пользователю после регистрации/входа
- фиксировать IP, user-agent и источник согласия

### Юридические согласия

В проекте также предусмотрены юридические соглашения, такие как:

- согласие на обработку персональных данных
- пользовательское соглашение
- запись информации о согласии в базу данных вместе с метаданными

## Схема базы данных

Используется PostgreSQL, а работа с ней идет через Sequelize.

Основные сущности, которые уже видны в коде:

### users

Содержит данные о пользователях:

- id
- email
- password
- role

### user_cookie_consents

Хранит информацию о cookie-согласиях:

- id
- user_id
- guest_token
- consent_type
- is_accepted
- version
- accepted_at
- expires_at
- is_revoked
- revoked_at
- revoked_reason
- ip_address
- user_agent
- source
- metadata

### user_legal_consents

Содержит юридические согласия пользователя или гостя, связанные с обработкой данных и соглашениями.

## API

Ниже описаны основные маршруты backend.

### Пользователи

#### POST /api/users/registration

Создание нового пользователя.

Пример запроса:

```json
{
  "email": "user@example.com",
  "password": "securePassword123",
  "privacyPolicyAccepted": true,
  "termsAccepted": true
}
```

#### POST /api/users/login

Вход пользователя.

```json
{
  "email": "user@example.com",
  "password": "securePassword123"
}
```

#### POST /api/users/logout

Выход пользователя из системы.

#### GET /api/users/me

Получение текущего авторизованного пользователя.

#### GET /api/users/

Получение списка пользователей.

### Cookie согласия

#### GET /api/cookie-consents/

Получение согласий текущего пользователя/гостя.

#### GET /api/cookie-consents/:consentType

Проверка конкретного согласия.

#### POST /api/cookie-consents/

Сохранение одного согласия.

#### POST /api/cookie-consents/all

Сохранение набора согласий сразу.

#### PUT /api/cookie-consents/:consentType/revoke

Отзыв согласия.

#### POST /api/cookie-consents/link

Связывание guest-согласий с пользователем.

## Подготовка окружения

### 1. Клонирование репозитория

```bash
git clone <repository-url>
cd WebPlant
```

### 2. Настройка PostgreSQL

Создайте базу данных и пользователя для проекта.

Пример:

```sql
CREATE DATABASE webplant;
CREATE USER webplant_user WITH PASSWORD 'your_password';
GRANT ALL PRIVILEGES ON DATABASE webplant TO webplant_user;
```

### 3. Создание .env файла для Backend

В папке `Backend` создайте файл `.env`:

```env
PORT=5000
DB_HOST=localhost
DB_PORT=5432
PGDATABASE=webplant
PGUSER=postgres
PGPASSWORD=your_password
SECRET_KEY=change_this_secret_key
```

Важно: 

- `SECRET_KEY` должен быть уникальным и безопасным
- для продакшена его нельзя хранить в репозитории
- значения должны быть заменены на реальные

## Безопасность и ограничения

Так как проект находится на ранней стадии разработки, следует учитывать:

- JWT используется в cookie и должен быть защищен настройками продакшн-среды
- в продакшене нужны дополнительные проверки CORS, HTTPS, rate limiting и защиты от bruteforce
- требуется настройка логирования и мониторинга
- требуется миграционная система для базы данных вместо простого `sequelize.sync()`
- нужно добавить валидацию всех входных данных и централизованную обработку ошибок
- скрытые/секретные данные не должны попадать в репозиторий
